# D 阶段 · 真机多角色验收清单

> 用途：让**真人**（不是开发者切角色）跑一遍完整业务闭环，暴露真实问题。
> 建议先拉 1~2 人试；跑通后再扩大范围。
> 出现问题时，按下表最后一节记录，反馈给开发者。

---

## 一、准备

| 步骤 | 操作 | 负责人 |
|---|---|---|
| 1 | 确认「版本管理 → 体验版本」是**最新版**（记下版本号） | 管理员 |
| 2 | 「成员管理 → 体验成员」添加同学微信号 | 管理员 |
| 3 | 把体验版二维码发给同学 | 管理员 |
| 4 | 同学扫码进入 → 管理员在「成员管理」给他们分配角色 | 管理员 |

**角色分配建议**（4 人即可覆盖全部路径）：

| 同学 | 角色 | 职责 |
|---|---|---|
| A | admin（超级管理员） | 建项目、分配角色、验收 |
| B | mentor（导师） | 建项目、布置任务、任命组长 |
| C | leader（组长） | 管理自己负责的项目与任务 |
| D | member（普通成员） | 接收任务、上传进度 |

---

## 二、验收步骤（按顺序做，每步打勾）

### 第 1 步：登录与身份（全员）
- [ ] 扫码进入后，首页显示自己的头像和昵称
- [ ] 首页顶部显示的角色与实际分配一致
- [ ] 点击「从微信选择头像 → 填写昵称 → 保存资料」，提示"保存成功"，头像变成自己选的

### 第 2 步：管理员布置（A 操作）
- [ ] 首页 → 新建项目 → 填名称/描述 → **选择项目负责人（B）** → 创建成功
- [ ] 进入该项目 → 新建任务 → **指派给 D** → 设置截止日期 → 创建成功
- [ ] 任务列表里"负责人"显示的是 **D 的昵称**（不是一串乱码）

### 第 3 步：导师能力（B 操作）
- [ ] 首页能看到「新建项目」按钮，且能创建成功
- [ ] 在**任意**项目里都能看到「新建任务」按钮，能布置任务并指派负责人
- [ ] 成员管理 → 进入 C 的详情 → 能把 C 设为「组长」，也能降回「普通成员」
- [ ] 尝试把别人设为「超级管理员」→ **应被拒绝**（提示只能任命组长或普通成员）

### 第 4 步：组长能力（C 操作）
- [ ] 「我的任务」顶部能看到「**我负责的项目**」区块，里面有 A 分配给自己的项目
- [ ] 能进入自己负责的项目 → 新建任务 → 指派给 D
- [ ] 尝试修改**别人负责的**项目 → **应被拒绝**

### 第 5 步：成员接收与上传（D 操作）
- [ ] 首页 → 我的任务 → 能看到指派给自己的任务（含所属项目、截止日期）
- [ ] 点进任务 → 拖动进度条到 50% → 改状态为「进行中」→ 保存
- [ ] **看到"保存成功"提示**
- [ ] 返回「我的任务」，进度显示为 50%
- [ ] 尝试修改**别人**的任务 → **应被拒绝**（提示没有权限）
- [ ] 任务详情页**看不到**「保存修改」以外的编辑按钮、看不到删除按钮

### 第 6 步：验收查看（A / B 操作）
- [ ] 首页 → 进度统计 → 总览数字与实际一致
- [ ] 「各项目进度」里能看到 D 上传后的进度变化
- [ ] 「成员任务分布」里能看到 D 名下的任务数与完成数
- [ ] 逾期任务显示为红色并标注"已逾期"

### 第 7 步：数据一致性（任意角色）
- [ ] A 把 D 的角色从「组长」改回「普通成员」→ D 退出小程序重新进入 → 各处显示一致
- [ ] 返回上一页时，列表/角色/进度都会自动刷新（不用手动下拉）

## 三、发现问题时怎么记录（发给开发者）

请按这个格式记录，信息越全定位越快：

```
【版本号】右上角「…」→ 关于 → 版本号 + 提交时间
【角色】  当前操作者是什么角色
【路径】  比如：首页 → 我的任务 → 点第一个任务 → 拖进度 → 保存
【预期】  我以为会发生什么
【实际】  实际发生了什么（有没有报错文字？按钮是没有还是点了没反应？）
【截图】  有就发
```

> 特别提示：如果**同一个问题只有某个人遇到**，先确认他的小程序版本号 —— 微信体验版有强缓存，版本不一致是最常见的"假 bug"。
