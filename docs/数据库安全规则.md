# 数据库安全规则说明（第 2 轮 · 权限闭环）

## 为什么要改

现在所有数据读写**都已经走云函数**（`utils/api.js` 统一调用，页面里没有直接用
`wx.cloud.database()` 的地方）。因此客户端**不应该**再有直接读写数据库的能力——
这是"权限不能只靠前端"的最后一道防线。

## 推荐设置（3 个集合都一样）

在 **云开发控制台 → 数据库 → 选中集合 → 权限设置 → 自定义安全规则**，填入：

```json
{
  "read": false,
  "write": false
}
```

含义：**客户端一律不能直接读写**，只有云函数（管理员权限）可以操作。

需要设置的集合：`users`、`projects`、`tasks`

## 怎么操作（每次约 20 秒）

1. 微信开发者工具 → 顶部「云开发」按钮 → 打开云开发控制台
2. 左侧「数据库」→ 点集合名 `users`
3. 右侧「权限设置」→ 选「自定义安全规则」
4. 粘贴上面的 JSON → 保存
5. 对 `projects`、`tasks` 重复

## 改完怎么验证

在项目根目录执行：

```
node .devtools/db.js
```

预期结果：三个集合的 `get()` 都返回**空数组**（客户端读不到），
而 `node .devtools/callfn.js getProjects '{}'` 仍能拿到 3 个项目
（云函数读得到）——这就说明规则生效了，且业务不受影响。

## 权限规则（业务层，已由云函数强制执行）

| 角色 | 说明 | 可做的事 |
|---|---|---|
| admin | 超级管理员 | 建/删项目、建/改/删任务、指派负责人、管理成员 |
| leader | 组长 | 管理**自己负责项目**下的任务；不能动别人的项目 |
| mentor | 导师 | 只读 |
| member | 普通成员 | 只读项目/任务；可更新**分配给自己的任务**的进度与状态 |

云函数 `updateTask` 已实现上述校验并通过测试（见下表）。

## 已验证的拦截效果

| 场景 | 结果 |
|---|---|
| admin 改任意任务 | ✅ 通过 |
| member 改「自己的任务」进度/状态 | ✅ 通过 |
| member 改任务标题等管理字段 | ❌ 被拒：只能修改自己任务的进度和状态 |
| member 改「别人的任务」 | ❌ 被拒：没有修改该任务的权限 |
| leader 改「非自己负责项目」的任务 | ❌ 被拒（**修复了原来的越权漏洞**） |
| leader 改「自己负责项目」的任务 | ✅ 通过 |
| mentor 改任务 | ❌ 被拒 |
