# 设计检查清单（改 UI 前后各过一遍）

> 数字标准来自 **Apple 人机界面指南（HIG）**，换算成小程序单位（本设备 750rpx = 390px，故 1pt ≈ 2.3px ≈ 4.6rpx）。
> 参考来源：[Apple HIG](https://developer.apple.com/design/human-interface-guidelines/)、
> [twostraws/SwiftUI-Agent-Skill · design.md](https://github.com/twostraws/SwiftUI-Agent-Skill/blob/main/swiftui-pro/references/design.md)（MIT）

---

## 1. 硬指标（必须达标）

| 项 | 标准 | 本项目实现 | 自查方式 |
|---|---|---|---|
| **可点区域** | **≥ 44×44pt**（≈88×88rpx） | 全局 `button { min-height: 88rpx }`；`.chip` / `.btn` / `.att-del` / `.mini` 均为 88rpx 行高 | `node .devtools/hig-audit.js` |
| 正文字号 | 17pt（≈34rpx） | `.t-title` 34rpx | 见 App.vue |
| 最小可用字号 | 不低于 11pt（≈22rpx），且**尽量不用** | `.t-weak` / `.hint` 22rpx（仅用于很次要的信息） | 同上 |
| 触控间距 | 相邻可点元素之间留足间隙 | `.btn` 之间 16rpx；`.chip` 靠分段控件内边距 | 目视 |

> 44pt 的意义：手指的舒适点击尺寸。低于这个值用户会频繁点不中（尤其在地铁/走动中）。

## 2. 视觉一致性（设计层已固化）

| 项 | 取值 |
|---|---|
| 主色 / 成功 / 警告 / 危险 | `#007AFF` / `#34C759` / `#FF9500` / `#FF3B30` |
| 分组底 / 卡片 | `#F2F2F7` / `#FFFFFF` |
| 文字：主 / 次 / 弱 / 占位 | `#1C1C1E` / `#6C6C70` / `#8E8E93` / `#C7C7CC` |
| 圆角 | 卡片 24rpx，控件 20rpx，胶囊 999rpx |
| 阴影 | 卡片几乎无阴影（`0 1rpx 3rpx rgba(0,0,0,.03)`），靠底色对比 |
| 分隔线 | `rgba(60,60,67,0.12)`，最后一行不画 |
| 页面边距 / 卡片内距 | 32rpx / 32rpx |

**状态徽章用 tinted 风格**（浅底 + 同色深字），例如进行中 = 底 `rgba(0,122,255,.12)` + 字 `#007AFF`。
**不要**改回高饱和大色块 —— 这是"有没有质感"的关键差别。

## 3. 交互与反馈

- [ ] 可点卡片/行有 `hover-class="pressed" hover-stay-time="60"`
- [ ] 按钮有反馈（全局 `button-hover` 透明度）
- [ ] 加载态用**骨架屏**（`.sk-card` × 2~3），不是「加载中…」文字
- [ ] 空状态用 `.empty-art`（CSS 画的文档图形）+ 一句人话说明下一步该干什么
- [ ] 危险操作（删除项目/归档成员）有二次确认弹窗，且确认按钮用红色
- [ ] 表单提交后有明确结果提示（本项目 `utils/api.js` 统一处理，注意 loading 与 toast 的时序）

## 4. 小程序特有的"做不到"（不要硬模仿 iOS）

| iOS 能力 | 小程序里的现状 |
|---|---|
| Dynamic Type（系统字号缩放） | ❌ 小程序不跟随系统字号，只能自己做"大字模式" |
| VoiceOver 无障碍标签 | ⚠️ 支持有限（`aria-label` 部分生效），重要按钮建议保留文字而非纯图标 |
| 真正的毛玻璃 | ⚠️ `backdrop-filter` 在 iOS 微信生效、部分安卓不生效 → 必须给半透明回退底色 |
| 系统级空状态组件 | ❌ 无（`ContentUnavailableView` 是 SwiftUI 的），所以自己画 CSS 插图 |
| 连续圆角（ConcentricRectangle） | ❌ WXSS 只有普通 `border-radius` |

## 5. 改 UI 的标准流程

```
1. 改 App.vue 设计层（改色板/组件要一次改全，别只改一个页面）
2. 页面里只写自己特有的样式，通用的一律复用 class
3. 编译 dev → 跑 node .devtools/phase-c-check.js（九页渲染 + 徽章色值 + 横向溢出 + 截图）
4. 跑 node .devtools/hig-audit.js（触点尺寸/字号）
5. 截图存 .devtools/shots/ 交给人过目 —— 美感这一项 AI 判断不了，必须人看
6. 提交 → 发行 → 上传体验版
```
